# 首次设置 TUI 设计

> 目标：让第一次使用的人**不需要读 README、不需要记参数**就能完成安装。
> 实现模块：`mcloud_fuse/tui.py`（通用组件）+ `mcloud_fuse/setup.py`（流程）。

## 设计原则

1. **一次只问一件事**：8 步，每步一个决定；`Esc` 可以回退，不丢已经填的内容。
2. **默认值就是推荐值**：一路 `Enter` 也能完成设置，结果是一个可用的挂载。
3. **不显示秘密**：token 粘贴时暂时退出界面（正常终端回显），只展示脱敏账号与到期时间。
4. **不依赖第三方 TUI 库**：只用标准库 `curses`，少一个会让 `pip install` 变重的依赖。
5. **一定有降级路径**：非 TTY / `--no-tui` / `--yes` 走行模式，脚本与 CI 不经过 curses。
6. **失败也要能看懂**：每一步执行结果用 `[OK] / [!] / [!!]` 标注，不在界面里抛 traceback。

## 流程

```text
欢迎 / 风险确认
   └─(Esc/q 退出)
      ↓
1 访问令牌 ── 已有 token？ ── 是 → 使用 / 自动续期 / 重新粘贴
      ↓                     └ 否 → 退出 curses 粘贴 → 校验 → 失败重试
2 挂载点（家目录 / /mnt/mcloud / 自定义；需要 root 时给 sudo 选项）
      ↓
3 共享访问（仅自己 / 其他本地用户只读 allow_other；检查 fuse.conf 与 o+x）
      ↓
4 云盘范围（菜单：整个云盘 / 输入云盘路径，如 /Photos/2026）
      ↓
5 缓存目录（输入，禁止与挂载点互相包含）
      ↓
6 删除方式（永久删除 / 回收站）
      ↓
7 覆盖写冲突（保留副本 / 报错）
      ↓
8 启动方式（systemd --user / 仅保存配置）
      ↓
确认页（摘要）── 开始执行 / 重新配置 / 退出
      ↓
执行页（保存 token → 写配置 → 验证账号 → 安装服务）
      ↓
完成页（结果列表 + 下一步命令）
```

### 2. 访问令牌

已有 token 时先给选择：

```text
┌ 访问令牌 ───────────────────────────────────────────── 步骤 1/8 ┐
│  令牌等同于账号访问权，只保存在本机 0600 文件里；向导不会显示明文。 │
│                                                                │
│  › 使用已保存的令牌                                            │
│    账号 138****8000；2026-12-02 到期（剩余 29.8 天）           │
│    尝试自动续期（无需粘贴）                                     │
│    调用续期接口延长有效期；失败时可以再粘贴新 token             │
│    重新粘贴令牌                                                │
│    从浏览器重新复制 Authorization，或整段 cURL                 │
│                                                                │
│  ↑↓ 选择   Enter 确认   Esc 上一步   q 退出                    │
└────────────────────────────────────────────────────────────────┘
```

token 已过期时没有「使用已保存的令牌」，第一项是「尝试自动续期」并默认选中：
先用续期接口试一次，失败再回到粘贴，尽量免去重新进浏览器复制。

选择“重新粘贴”会**暂时退出 curses**，打印操作步骤，等待粘贴到 `Ctrl-D`：

```text
请先在浏览器里拿到 token：
  1. 打开 https://yun.139.com/ 并确认已登录
  2. 按 F12 → Network → 过滤 file/list → 点任意一条请求
  3. 右侧 Request Headers → 复制 `Authorization: Basic ...` 整行
     （或右键该请求 → Copy → Copy as cURL）

粘贴到下面，按 Ctrl-D 结束；直接 Ctrl-D 表示跳过。
```

校验失败不会退出向导，而是回到粘贴页并给出原因（Cookie、base64 非法、已过期）。

「尝试自动续期」调用客户端已有的 `tellin/authTokenRefresh.do`：成功则直接进入下一步，
失败会显示原因并继续留在粘贴流程。它只使用已保存的 Basic token，不读取浏览器
Cookie，也不实现账号密码登录（见 ADR-0002）。服务运行期间也会每 12 小时做一次
同样的检查，剩余不足 15 天才真正请求；`systemctl --user status mcloud-fuse`
的 `Status:` 会显示脱敏账号与剩余天数。

### 3. 挂载点：先选位置，再决定要不要 sudo

第一屏是三个入口，覆盖「自己用」和「放在系统目录」两种常见需求：

```text
┌ 挂载点 ─────────────────────────────────────────────── 步骤 2/8 ┐
│  云盘内容会出现在这个目录；不存在时会按这里的选项创建。           │
│                                                                │
│  › 家目录（推荐）                                              │
│    /home/you/mnt/mcloud；只给自己用，不需要 root               │
│    系统目录 /mnt/mcloud                                        │
│    本机所有用户都能进入；需要 sudo 创建一次                     │
│    自定义路径                                                  │
│    任意绝对路径，例如 /srv/cloud 或 /mnt/data/cloud            │
│                                                                │
│  ↑↓ 选择   Enter 确认   Esc 上一步   q 退出                    │
└────────────────────────────────────────────────────────────────┘
```

选「自定义」才进输入框；选前两项直接校验。目录建不出来（典型是 `/mnt`
只有 root 可写）时，不抛错误，而是给出可执行的命令和三个选择：

```text
┌ 需要 root 创建 ───────────────────────────────────────────────┐
│  /mnt/mcloud 还不存在，/mnt 只允许 root 写入                   │
│                                                                │
│  将执行：                                                      │
│    sudo install -d -m 755 -o you -g you /mnt/mcloud            │
│                                                                │
│  › 用 sudo 创建（会暂时离开界面）                              │
│    退出全屏后在正常终端里执行，可能要输密码                     │
│    我已经手动建好了，重试                                      │
│    换一个路径                                                  │
│                                                                │
│  ↑↓ 选择   Enter 确认   q 退出                                 │
└────────────────────────────────────────────────────────────────┘
```

选「用 sudo 创建」时 `Screen.suspend()` 先 `endwin()`，把终端还给 shell，
sudo 的密码提示因此是正常的；命令结束再 `resume()` 重绘。**只提权这一次**：
之后的挂载、卸载、systemd 用户服务都以普通用户运行。

校验规则（`setup.validate_mountpoint` → `mountopts.inspect_mountpoint`）：

- 非空、绝对路径（`~` 会被展开）；
- 不能是 `/`、不能是符号链接、不能已经是挂载点；
- 已存在：必须是目录，且当前用户可读写执行，否则走上面的 sudo 分支；
- 不存在：最近的可写父目录能建就直接建，否则同样走 sudo 分支。

### 4. 共享访问：默认关，开了就是只读

```text
┌ 共享访问 ───────────────────────────────────────────── 步骤 3/8 ┐
│  挂载默认只有你自己能访问；开启后本机其他用户可只读浏览，写入仍被拒绝。│
│                                                                │
│  › 仅自己（推荐）                                              │
│    不需要 root，也不需要改 /etc/fuse.conf                      │
│    其他本地用户可读（allow_other）                             │
│    需要 /etc/fuse.conf 里的 user_allow_other；文件固定 0644、目录 0755│
│                                                                │
│  ↑↓ 选择   Enter 确认   Esc 上一步   q 退出                    │
└────────────────────────────────────────────────────────────────┘
```

选「其他本地用户可读」后，向导按顺序把两个前提补上：

```text
┌ 还差一步：user_allow_other ────────────────────────────────────┐
│  非 root 挂载时，FUSE 只在 /etc/fuse.conf 允许时才接受 allow_other。│
│                                                                │
│  将执行：                                                      │
│    sudo sh -c "grep -qs '^user_allow_other' /etc/fuse.conf ||  │
│      echo user_allow_other >> /etc/fuse.conf"                  │
│                                                                │
│  只追加一行，不动其它配置。                                    │
│                                                                │
│  › 用 sudo 写入（会暂时离开界面）                              │
│    sudo 可能要输入密码                                         │
│    我已经手动改好了，重试                                      │
│    算了，仅自己访问                                            │
└────────────────────────────────────────────────────────────────┘
```

然后是路径可穿越性检查：从 `/` 到挂载点父目录的每一级都要有 `o+x`。
`~/mnt/mcloud` 常被 `0700` 的 `$HOME` 挡住，这时向导列出具体目录和
`sudo chmod o+x <dir>`，并让用户选「仍然开启 / 改为仅自己」——不静默改家目录权限。

语义（`allow_other` + `default_permissions`，attrs 固定 `0644/0755`）：

| 谁 | 能做什么 |
| --- | --- |
| 当前用户 | 读写，和原来一样 |
| 其他本地用户 | 只读；写、删、改名被内核按 mode 拒绝 |
| 网页端 / App | 不受影响，仍是账号内全权 |

行模式对应：`setup --allow-other` / `--no-allow-other`；挂载时临时覆盖用
`mcloud-fuse mount --allow-other`。诊断用 `mcloud-fuse doctor` 的
`user_allow_other` 与「父目录可穿越」两项。

## 降级与兼容

| 条件 | 行为 |
| --- | --- |
| stdin/stdout 不是 TTY | 自动走行模式，不初始化 curses |
| `--no-tui` | 强制行模式 |
| `--yes` / `-y` | 行模式 + 全部默认值（仍要求 token） |
| `--token-stdin` | 从标准输入读 token，适合自动化 |
| `--refresh-token` | 先用续期接口延长已保存的 token，失败再粘贴 |
| `TERM` 不可用 | `tui.run` 抛 `TuiUnavailable`，回退行模式 |
| 终端小于 60x16 | 显示提示并等待调整，不直接崩溃 |
| 没有颜色 | `attr()` 退化为 `A_BOLD` / `A_REVERSE`，布局不变 |

行模式与 TUI 共用同一套 `SetupPlan`、校验函数与 `execute()`，不会出现
“向导能过、脚本不能过”的双重标准。

## 错误处理

- **令牌错误**：回到粘贴页，给出 Cookie / base64 / 过期三类明确提示。
- **自动续期失败**：显示接口原因（通常是设备指纹），仍可继续粘贴；不影响挂载。
- **路径错误**：留在当前输入页，错误信息显示在输入框下方，不清空已输入内容。
- **写配置失败**：执行页标记 `[!!]` 并停止后续步骤（服务不会安装）。
- **账号验证失败**：标记 `[!]` 警告但继续；配置已保存，可稍后 `doctor`。
- **服务安装失败**：标记 `[!]` 警告；配置保留，提示手动 `mcloud-fuse`。
- 向导不打印 traceback，也不把 token 写进异常信息。

## 代码结构

```text
mcloud_fuse/
├── tui.py          # Screen：边框、菜单、输入、消息、进度、宽度/折行/行编辑
├── setup.py        # 流程状态机、8 步页面、校验、行模式、execute()
├── mountopts.py    # 挂载点位置、sudo 命令生成、allow_other 前置条件（纯逻辑）
├── userconfig.py   # config.json 的读写与 0600、环境变量注入
├── tokens.py       # token 解析/脱敏/落盘（脚本与向导共用）
├── token_status.py # 12 小时心跳、systemd STATUS、临近过期自动续期
├── token_cli.py    # mcloud-fuse token status|refresh
└── service.py      # systemd --user 单元生成、安装、状态
```

`tui.py` 里可测试的纯逻辑（`display_width`、`clip`、`wrap_text`、`LineEditor`、
`visible_field`）与 curses 渲染分离；CI 不需要 TTY 就能覆盖这些部分。
