# 性能基线

- 日期：2026-10-28
- 版本：v0.4.0
- 主机：ASUS TUF Gaming A15（Linux），网络为家庭宽带
- 挂载点：`/tmp/mcloud-dsh`
- 脚本：`scripts/bench_mount.py`

> 所有数字都是**单次实测**，受云端调度、网络与缓存影响。脚本会在
> `_mcloud_bench_*` 下建对象并清理；大目录列举是只读的。
>
> 注：v0.4.0 后期默认改为全量懒加载（`open()` 不下载、`read()` 按 4MiB Range），
> 本页的冷读/顺序读数字代表旧的混合策略，作为大目录与上传/删除的基线仍有参考价值。

## 1. 结论摘要

1. **大目录首次列举是最大瓶颈**：12,049 项约 50–73 秒，主要花在
   `/file/list` 的游标分页上（约 25 页 × 2–3 秒/页），不是 FUSE 本地开销。
2. **页大小从 100 提到 500** 只带来有限改善（同一条目数下页数减少，但服务端
   单页耗时上升）；`pageSize=1000` 服务端最多回 666 条，总耗时反而更差。
   当前保留 500。
3. **去掉缩略图字段**（`imageThumbnailStyleList`）每页快约 15–30%，
   FUSE 用不到缩略图，已移除。
4. **删除批处理收益最大**：`rm` 20 个文件从 13.8 秒降到 0.6 秒。
   做法是本地立即隐藏 + 后台合并成一次 `batchDelete`，不再逐个等异步任务。
5. **上传约 9.7 MiB/s**（100 MiB / 10.3 秒），与上游带宽一致；热读受本地缓存
   影响约 300–600 MiB/s；冷读约 4.7 MiB/s（3.7 MB PDF / 0.8 秒）。
6. 元数据热路径（根目录 `ls`、`stat`）已经是毫秒级，TTL 缓存有效。

## 3. 调优内容

### 3.1 页大小 500

服务端限制：`pageSize` 最小 1、最大 1000，超过直接报错。

实测（12,049 项目录）：

| pageSize | 页数 | 总耗时 |
| ---: | ---: | ---: |
| 100 | ~121 | 59s |
| 500 | ~25 | 50–73s |
| 1000 | 19（每页最多 666 条） | 66s |

结论：500 是相对稳妥的默认值；再大没有收益。

### 3.2 移除缩略图请求

`/file/list` 原本带 `imageThumbnailStyleList: ["Small","Large"]`。
单页 500 条的对比：

| 请求 | 单页耗时 |
| --- | ---: |
| 带缩略图 | 4.5s |
| 不带 | 3.7s |
| 空数组 | 3.1s |

FUSE 不使用缩略图，已从请求体删除。注意这不改变返回字段契约，
`tests/contracts/file_list.json` 里仍保留 `thumbnailUrls` 字段。

### 3.3 删除批处理

原实现：`unlink` → `batchDelete` → 轮询 `task/get` 到 `Succeed` 才返回。
单文件约 0.7 秒，`rm -rf` 线性放大。

现实现：

1. `unlink` 立即把 fileId 加入本地隐藏集（60 秒），列举时过滤；
2. 投入后台队列，worker 在 100ms 内合并成一次 `batchDelete`；
3. 不再阻塞 `unlink`；卸载前 `flush_deletes()` 等待队列提交。

效果：`rm` 20 个文件 13.8s → 0.63s。代价是“云端真正删完”比 `unlink` 返回稍晚，
但本地视图已立即一致，且卸载前会等待提交。

### 3.4 rename 竞态修复

benchmark 暴露：刚写完的文件还在后台上传，`rename` 拿到的是 `pending-*`，
API 返回 EIO。现在 `rename` 先 `_wait_inflight_commit`，再调 `/file/update`。

## 4. 没有解决的问题

### 大目录首次列举仍是 50 秒级

游标分页必须串行：拿到 `nextPageCursor` 才能取下一页，无法并行。可能的改进：

- **增量 readdir**：先返回第一页，后台继续拉，目录内容逐步出现；
  但 `ls` 仍会读到 EOF，收益主要在交互式补全/文件管理器；
- 服务端若提供更粗粒度的枚举/导出接口（目前没有）；
- 本地持久化目录快照：重启后先展示旧快照，再后台对账（复杂，且有陈旧视图风险）。

当前选择：**接受首次慢，之后走内存树/元数据缓存**，并在文档里写清。

### 冷读吞吐

4.7 MiB/s 是单连接顺序下载的结果。可尝试：

- Range 分片并行预取（当前 4 MiB 串行）；
- 服务端直链是否支持多连接（未验证）。

## 5. 复现方式

```bash
# 挂载后
python3 scripts/bench_mount.py \
  --mount /mnt/mcloud \
  --large-dir /mnt/mcloud/某个大目录 \
  --json-out /tmp/bench.json \
  --md-out /tmp/bench.md
```

冷读：

```bash
python3 scripts/bench_mount.py --mount /mnt/mcloud --read-only /mnt/mcloud/某个文件
```

注意：

- 热读命中本地缓存，不代表云端读性能；
- 大目录列举会随云端负载波动（本次 50–73s）；
- 测试会创建 `_mcloud_bench_*` 并删除，若中断请手工清理。
